### Slide 6: Identity Profiles
- **Layout:** `Title, Content`
- **Extracted Text Hierarchy:**
  - An identity profile is a template for creating identities, and a place where identity policy is defined.
    - Commonly Aligned to Identity ‘type’ - i.e. Employees, Contractors, Students, Faculty, etc.
  - Configured by in the admin interface:
    - Admin > Identities > Identity Profiles.
  - An identity can only be assigned by a single identity profile.
    - Implicit priority / ordering in the user interface.
    - Priority can also be adjusted by REST API.

### Slide 7: Identity Profile Settings
- **Layout:** `Title, Content`
- **Extracted Text Hierarchy:**
  - Settings define policy about the identity profile.
  - The Account Source section defines the authoritative source.
  - The Sign-in Method defines the authentication source for the user.
    - e.g. IdentityNow, Active Directory
  - There are additional options for how and where a user can sign-in.
    - Off Network
    - Untrusted Geographies
    - Strong authentication

### Slide 18: Untitled Slide
- **Layout:** `Title`
- **Media Assets:** `assets/image43.png`
- **Presenter Notes:**
  > Access Profiles: one or more entitlements from a single source system (application) bundled and should be assigned as one unit. 
  > User’s can also request Access Profiles directly through the IDN Request Center.
  > Optional approval process (for AP) (if configured) when requesting access 
  > 
  > Detection: IDN compares (after aggregation of accounts and entitlements) the entitlements held by the user with the entitlements bundled on the access profile.
  > If the identity has all the entitlements contained within the access profile, the access profile is detected (and enabled) for that identity.
