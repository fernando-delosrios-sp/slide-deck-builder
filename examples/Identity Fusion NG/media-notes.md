# Visual Media Notes: Identity Fusion NG - Introduction.pptx

Visual audit of extracted presentation slide assets from `deck/assets/`:

- **image1.png** — Cover Slide Hero Graphic: Title "Identity Fusion NG" with subtitle "Map, Define, Match: messy multi-source accounts into one identity story" and description card on abstract blue flowing ribbon background.
- **image2.png** — Architectural Comparison Diagram: "Without Fusion" (HR Account + AD Account crossing with "Disconnected / No Match Found" into two separate identities) versus "With Fusion" (HR and AD accounts flowing into Continuous Purification Pipeline [Map] -> [Define] -> [Match] resulting in "One identity story").
- **image3.png** — Pipeline & Exits Flowchart: "Continuous Purification Pipeline" receiving Managed sources and ISC identities (scope on) into chevron pipeline [Map] -> [Define] -> [Match], branching into 4 exits: Fusion account, Review form, Automatic merge, and Drop (Records and Orphan).
- **image4.png** — Source Participant Matrix Table: Matrix mapping 5 participant types (identity in scope, correlated managed account, uncorrelated Authoritative account, uncorrelated Records account, uncorrelated Orphan account) across 4 capabilities: seed, enter Match, contribute attributes, and non-match exit.
- **image5.png** — Deployment Architecture Comparison: "Umbrella Deployment" (Fusion source is authoritative and owns identity creation) versus "Side-car Deployment" (Fusion source is non-authoritative; managed sources create identities while Fusion provides merged attributes).
- **image6.png** — Merge Strategy Schema Diagram: Source attributes (Workday title="Solutions Consultant", SuccessFactors title="Sales Engineer") flowing into merge engine cog (main account, origin account, first found, list, concatenate, source name) emitting consolidated `jobTitle = [Solutions Consultant] [Sales Engineer]`.
- **image7.png** — Execution Pipeline Timeline: Step-by-step lifecycle showing Map -> Normal Define (normalised names/dates before Match) -> Match scoring -> Unique Define (usernames, employee IDs, counters minted only after Match decides).
- **image8.png** — Match Scoring Threshold Funnel: Two-stage funnel showing uncorrelated accounts evaluated against Auto-merge threshold (exiting to Automatic merge) and Review floor (exiting to Review form), with below-floor falling to Non-match (create identity, register value, or drop account).
- **image9.png** — Match Scoring & Mandatory Rule Veto Table: Worked scoring example with Enhanced Name Matcher (Jane/Jayne), Binary employee ID (E-1042), Skip if missing (department), and a mandatory rule veto (clearance status Secret vs Confidential causing rejection despite high score).
- **image10.png** — Governance & Review Flow: Process diagram showing Review form -> Assigned reviewer -> Decision (link or create) -> Next aggregation (showing decisions take effect on subsequent run, not immediately).
- **image11.png** — Matching vs Correlation Distinction Diagram: Conceptual flow illustrating that "Matching decides who this account is" -> [Identity exists] -> "Correlation links the account to an ISC identity", featuring key correlation strategies (Correlate on aggregation, Reverse correlation, Do not correlate, Enforced correlation role).
- **image12.png** — Fusion Account Record Architecture: Central operator card for `Operator_01` (Identity ID, Role, Last Active, Status) linked to Provenance tracking, Source Data aggregation options, and Entitlements (status vs action).
- **image13.png** — External Settings Gateway Capabilities: Gateway hub branching into four operational capabilities: Proxy mode, Scenario recording, External logging, and Dry-run execution.
- **image14.png** — Extensibility Architecture Pipeline: Developer extension model showing ISC standard operations -> Override Seam 1 (Operation handler) -> Override Seam 2 (Service registry) -> Mapping/Define/Match services -> ISC Exit.
- **image15.png** — Solution Archetypes Matrix: Four adoption path cards with icons and reading lists: HR and AD deduplication (umbrella mode), Username/employee-ID pool (Records source), Contractor cleanup (Orphan source), and Attribute consolidation only (side-car mode).
